## Project Overview

Single-package Next.js 16 (App Router) + React 19 + TypeScript app. Serves a CPF exam tryout platform (Indonesian civil servant selection) with landing, dashboard, and admin sections.

## Tech Stack

- **Next.js 16.2.3** / React 19.2.4 — App Router, server components by default
- **Tailwind CSS v4** — configured via `@tailwindcss/postcss` (CSS classes differ from v3; use v4 syntax)
- **Zustand 5** — client state (`store/useAuthStore.ts`, `store/useAppStore.ts`)
- **TypeScript** — strict mode, `moduleResolution: bundler`
- **Vitest** — unit/integration testing with `@testing-library/react` + `jsdom`
- **No Prettier** — only ESLint (`eslint.config.mjs`)

## Key Commands

```bash
npm run dev      # start dev server on :3000
npm run build    # production build
npm run lint     # ESLint only (no typecheck script)
npm run start    # production server
```

## Architecture

| Path | Purpose |
|---|---|
| `app/page.tsx` | Landing page redirect (entry point) |
| `app/dashboard/` | User dashboard (tryout, ranking, profile, payment, buy, video) |
| `app/admin/` | Admin panel (landing, settings, payments, soal/question editor) |
| `app/api/` | API routes |
| `components/landing/` | Landing page components |
| `components/admin/` | Admin UI components |
| `components/ui/` | Shared UI primitives (Badge, Button, Card, Modal, etc.) |
| `store/useAuthStore.ts` | Auth state (user, role, isAuthenticated) |
| `store/useAppStore.ts` | App data state (packages, questions, tryout sets, logo config) |
| `lib/types.ts` | All TypeScript interfaces |
| `lib/scoring.ts` | TWK+TIU+TKP scoring logic |
| `data/questions.ts` | Static question bank (110 questions) |
| `data/packages.ts` | Static package definitions |

## State Management

State is client-side via Zustand. Server components read store data passed as props — they do NOT import the store directly. The `appStore` initializes from `data/questions.ts` and `data/packages.ts`.

## Tailwind v4 Notes

This project uses Tailwind v4 (not v3). Key differences:
- Use `@theme` in CSS instead of `tailwind.config.js` for custom values
- CSS variables for colors (`--color-*`) are the primary mechanism
- Check `app/globals.css` for the actual theme tokens

## Testing (Vitest + Testing Library)

```bash
npm run test        # run all tests once
npm run test:watch # run tests in watch mode
npm run test:coverage # run with coverage report
```

### Test File Convention

Tests are **co-located** next to the source file they test:

```
lib/scoring.test.ts              # tests for lib/scoring.ts
store/useAuthStore.test.ts       # tests for store/useAuthStore.ts
store/useAppStore.test.ts        # tests for store/useAppStore.ts
components/ui/Button.test.tsx    # tests for components/ui/Button.tsx
components/ui/Modal.test.tsx    # tests for components/ui/Modal.tsx
app/api/auth/route.test.ts       # tests for app/api/auth/route.ts
```

### TDD Workflow

1. Write a failing test → 2. Run `npm run test:watch` to see red → 3. Implement minimum code to pass → 4. See green → 5. Refactor → 6. Repeat

### Pre-commit Hook

`lint-staged` runs `vitest related --run` + `eslint` on staged `*.ts(x)` files before each commit. The hook is at `.husky/pre-commit`.

### What to Test

| Priority | Target | Why |
|---|---|---|
| High | `lib/scoring.ts` | Pure functions, no DOM, highest confidence |
| High | Zustand stores | State transitions are easy to assert |
| Medium | `components/ui/*` | Shared primitives, breaking changes are costly |
| Medium | `app/api/*/route.ts` | Filter logic, edge cases |
| Low | Page components | Require more setup (mocking layouts, providers) |
